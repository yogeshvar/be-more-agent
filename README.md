# Beemboy

Python assistant that talks to **llama.cpp `llama-server`** (OpenAI-compatible HTTP API) and runs an agent loop with **MCP** tools (default: **Brave Search** when `BRAVE_API_KEY` is set).

## Prerequisites

- `llama-server` built from [llama.cpp](https://github.com/ggml-org/llama.cpp), started with **`--jinja`** and a tool-capable chat template.
- Python 3.11+
- For Brave MCP: Node + `npx` on `PATH`

## Setup

```bash
cd /path/to/be-more-agent
python -m venv .venv && source .venv/bin/activate
pip install -e .
```

Copy `.env.example` to `.env` and adjust.

## Run

1. Start the server (example):

   `llama-server --jinja -m /path/to/model.gguf --host 127.0.0.1 --port 8080`

2. Chat:

   `beemboy` (or `python -m beemboy`)

3. Voice mode (offline wake/STT/TTS):

   `beemboy voice`

4. Desktop UI mode (camera preview + identity panel + safe save/exit):

   `beemboy ui`

### Optional: turn telemetry / observability

Use `--telemetry` to print per-turn debug metrics to stderr while keeping normal assistant output in stdout:

```bash
beemboy chat --telemetry
```

`--verbose` (`-v`) also enables telemetry, plus structlog debug logs:

```bash
beemboy chat --verbose
```

Telemetry line format:

```text
[telemetry] {"type":"turn_telemetry","turn":1,"metrics":{...}}
```

Key metrics:

- `input.tokens_est_total`: heuristic estimated tokens sent to the model across all LLM rounds in a turn.
- `output.tokens_est_total`: heuristic estimated tokens generated by the model across all rounds.
- `input.chars_total` / `output.chars_total`: raw character totals (backup when exact tokenizer counts are unavailable).
- `latency_ms.prep`: request-build time before the first LLM call (prompt + context + history assembly).
- `latency_ms.llm_total`: summed LLM API time for all model calls in the turn.
- `latency_ms.tools_total`: summed MCP tool execution time in the turn.
- `latency_ms.turn_total`: full end-to-end turn latency.
- `tool_calls[]`: per-tool timing plus argument/result character sizes.
- `llm_rounds[]`: per-round input/output estimates and model latency.

Token estimation is intentionally lightweight and offline-friendly (`~1 token per 4 chars`), so values are best treated as relative/debug guidance rather than billing-accurate counts.

## Voice Stack (V2, offline-first)

Beemboy now includes a local voice pipeline in `src/beemboy/voice/`:

- **Wake word:** ONNX wake model for "Beemboy" (`OnnxWakeWordDetector`)
- **STT:** `whisper.cpp` CLI (`whisper-cli`)
- **TTS:** Piper CLI (`piper`)
- **Conversational follow-up:** short post-response listening window (no wake word needed)

### Voice prerequisites

- Linux/Raspberry Pi 5 recommended (default playback command is `aplay`).
- Python packages:

  ```bash
  pip install -e .
  pip install numpy onnxruntime sounddevice
  ```

- Native tools on `PATH`:
  - `whisper-cli` (from [`whisper.cpp`](https://github.com/ggml-org/whisper.cpp))
  - `piper` (from [`rhasspy/piper`](https://github.com/rhasspy/piper))
- Local models:
  - wake model (already in repo): `assets/wakeword/beemboy.onnx`
  - whisper model: `models/ggml-base.en.bin`
  - piper model: `models/en_US-lessac-medium.onnx`

### Voice configuration (minimal)

Set the main paths/thresholds in `.env`:

```bash
VOICE_WAKE_MODEL_PATH=assets/wakeword/beemboy.onnx
VOICE_WAKE_THRESHOLD=0.52
VOICE_WHISPER_MODEL_PATH=models/ggml-base.en.bin
VOICE_PIPER_MODEL_PATH=models/en_US-lessac-medium.onnx
VOICE_FOLLOWUP_SECONDS=3.5
```

Optional knobs are available for mic device, silence detection, and playback command, but defaults are tuned for low-friction Pi usage.

### Run voice mode

```bash
beemboy voice
```

With telemetry:

```bash
beemboy voice --telemetry
```

## Configuration

See `.env.example` for `LLAMA_*`, `BRAVE_*`, optional `MCP_SERVERS` JSON, live-context options, and **`STREAM_RESPONSES`** (token streaming to the terminal while the model generates).

Phase 1 adds:

- Prompt-pack files in `prompts/` loaded in fixed order (`core_persona`, `response_style`, `memory_usage`, `tool_policy`, `vision_policy`).
- Durable local memory persisted to `MEMORY_STORE_PATH` (defaults to `.beemboy_memory.json`).
- Internal context compression before model calls (memory block + packed older history). Disable with `CONTEXT_COMPRESSION=false`.

## Camera Identity (V1 focused flow)

Beemboy now includes an offline-first camera identity pipeline in `src/beemboy/vision/`:

- face detection (`FaceDetector`, OpenCV optional)
- deterministic lightweight embeddings (`FaceEmbedder`)
- persistent embeddings-only identity registry (`FaceRegistry`)
- recognition + unknown enrollment flow (`CameraIdentityPipeline`)

Behavior:

- **Known match**: identity context is injected into the system prompt so greetings can be personalized.
- **Unknown match**: Beemboy asks for the person's name, then treats the next utterance as the enrollment name and stores only embeddings + identity metadata.

Enable in `.env`:

```bash
CAMERA_ENABLED=true
CAMERA_IDENTITY_STORE_PATH=.beemboy_identities.json
CAMERA_MATCH_THRESHOLD=0.82
```

Optional debug commands in chat mode when camera is enabled:

- `/camera-embedding 1,0,0,...` to submit an embedding directly.
- `/camera-frame /path/to/frame.jpg` to run detector+embedding against a still frame.

## Desktop UI (pre-V3 operator surface)

`beemboy ui` launches a lightweight Tkinter app intended for local desktop/Pi operation:

- live camera preview area (when OpenCV camera access is available),
- known identities panel (from local memory + face registry),
- recognition status feed,
- explicit controls for **Start**, **Stop**, **Save now**, and **Safe Exit**.

Safe Exit behavior:

- stops the camera/recognition loop,
- flushes local memory store,
- flushes face identity registry,
- releases camera resources before closing the window.

UI-specific environment knobs:

```bash
UI_ASSETS_PATH=assets
UI_POLL_INTERVAL_MS=120
```

`UI_ASSETS_PATH` is used for icon/thumbnail visuals when files exist. If assets are missing, the app falls back to text placeholders and remains functional.

Pi 5 default guidance:

- keep `CAMERA_DETECTOR_BACKEND=opencv` only if OpenCV is installed and tuned for your camera;
- otherwise set `CAMERA_DETECTOR_BACKEND=none` and feed embeddings from an external lightweight detector/encoder process.

By default, if you provide no MCP configuration, Beemboy auto-enables a built-in MCP trio via `uvx`:

- `time` (`mcp-server-time`)
- `fetch` (`mcp-server-fetch`)
- `ddg-search` (`duckduckgo-mcp-server`)

You can disable this fallback with `DEFAULT_MCP_ENABLED=false`. If you want a specific timezone for the time server, set `DEFAULT_TIME_TIMEZONE`.

Note: this default trio requires `uvx` (from `uv`) to be installed on your system.

## MCP in the llama-server Web UI (`mcp-proxy`)

This flow is for the **llama-server built-in Web UI**, which can talk to MCP servers through a small proxy.

**Beemboy** can use the **same** `mcp-proxy` without hand-writing URLs:

- Set **`MCP_PROXY_BASE_URL`** (e.g. `http://127.0.0.1:8001`).
- Set **`MCP_PROXY_CONFIG`** to your `mcp-proxy` JSON (the file with `"mcpServers": { ... }`), *or* set **`MCP_PROXY_SERVERS`** to a comma-separated list of those server names (`time,fetch,ddg-search`).
- Keep **`MCP_PROXY_URL_SUFFIX=mcp`** unless you need **`sse`** endpoints instead.

Alternatively, add each URL manually in **`MCP_SERVERS`**, for example:

`{"id":"time","transport":"http","url":"http://127.0.0.1:8001/servers/time/mcp"}`

### 1. Start `llama-server` with the Web UI MCP hook

Enable the flag that wires the Web UI to MCP (community write-ups refer to this as **`--webui-mcp-proxy`**). Keep **`--jinja`** if you rely on tool-capable chat templates. Example:

```bash
llama-server --jinja --webui-mcp-proxy -m /path/to/model.gguf --host 127.0.0.1 --port 8080
```

### 2. Install `uv`

[`uv`](https://docs.astral.sh/uv/getting-started/installation/) is used to run `uvx` and the proxy.

### 3. MCP server config

Copy [`config/mcp-proxy.example.json`](config/mcp-proxy.example.json) to a directory you control (e.g. `cp config/mcp-proxy.example.json ./mcp-config.json`) and edit it. If you use the **time** server, set **`--local-timezone=...`** to your real timezone.

### 4. Run `mcp-proxy`

From the **same directory** as your config file:

```bash
uvx mcp-proxy --named-server-config mcp-config.json --allow-origin "*" --port 8001 --stateless
```

The proxy prints a URL per named server. For the Web UI, use the endpoint that ends with **`/mcp`**, not **`/sse`**. Example:

- Given: `http://127.0.0.1:8001/servers/time/sse`
- Use in the UI: `http://127.0.0.1:8001/servers/time/mcp`

### 5. Register servers in the Web UI

1. Open the llama-server Web UI.
2. Go to **Settings → MCP → Add New Server**.
3. Add each server URL (the `.../mcp` form), e.g.  
   `http://127.0.0.1:8001/servers/time/mcp`  
   `http://127.0.0.1:8001/servers/fetch/mcp`  
   `http://127.0.0.1:8001/servers/ddg-search/mcp`
4. Save each server and **enable** it with the toggle. Some servers may need **“use llama-server proxy”** enabled if the UI offers it.

After that, those MCP tools should be available in the Web UI chat.
